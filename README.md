# 通用角色 QQ 接入 — 0.5.1

下文旧版本章节保留历史说明；新版章节的行为优先。

## 0.5.1：自主活动联动

提供 niaQQ 服务给自主活动插件；可按稳定人物 ID 将活动联系意图送到当前私聊。尊重活动插件的 QQ 安静时段、演练和停止状态，目标的新消息先处理。明确要求不要再主动联系时，暂停该私聊的自主联系，正常聊天不受影响；可在聊天页恢复。私人来源仍按现有记忆范围检查。

## 0.5.0：上下文超限兜底续接

平时复用原 DSH 会话，沿用宿主或 billion-context 已有的压缩。不会按日期、闲置时间、消息条数或磁盘大小新开会话。

`autoContinue` 默认 true：只观察整轮最终 `turn/end` 的 `reason.kind=error` 且 `error.code=CONTEXT_WINDOW_EXCEEDED`。压缩和适配器重试先运行；限流、网络超时、认证失败和 UNKNOWN 不触发。每个模式每小时最多自动尝试一次，同一个失败源会话不反复自动尝试。摘要失败后保留原会话，面板可重试。

“聊天”页提供“新开并续接”、进度、重试、取消及旧会话 ID；页面打开时每两秒刷新状态。连接配置的“恢复与兼容”可关闭自动续接。

续接等当前回合及发送链结束，在 DSH `runMaintenance` 独占区内进行。交接使用当前模型的独立无工具请求，最多等待 45 秒，生成一份摘要；同时保留受长度限制的近期输入、实际 QQ 回执和近期工具结果。仅写入新会话背景不会唤醒模型或外发消息。旧会话文件保留，历史关联保存在 `sessionHistory`。

新会话加载原角色工作区、当前 provider/model/reasoningEffort、预设，以及现有记忆/情绪；稳定 chatId、人物 ID 和 personaId 不变。联动模式的预演继续使用独立会话与数据范围。旧会话的 QQ 工具拒绝继续操作当前聊天，防止从旧窗口重复发送。

新会话与交接持久化完成后才原子更新 `sessionId`/`previewSessionId`。准备失败、原会话或候选会话在交接时收到新操作、关闭插件、未核实的投递/外发/联系意图或缺少工具回执时不切换。期间 QQ 新消息继续进入原聊天队列，切换后仍只处理一次。

自动续接后，仅对上一轮尚未调用工具的 QQ 输入尝试继续回应；不把旧输入重新入库或再计情绪。期间出现新消息则放弃旧回复，先处理新内容。有工具操作的旧回合不自动重放。恢复投递中发生中断时标记待核实，不自动重试；面板可“停止恢复旧消息”。

交接摘要可能遗漏或误解细节，无法保证无损；精确旧内容仍查原会话和记忆。已有压缩已经减少的上下文不会被完整展开搬运。每次续接额外消耗一次摘要模型请求。若新会话仍超限，冷却机制会阻止循环建会话；需检查实际模型窗口和基础提示占用。

本版也修正 QQ 接话事件对 DSH `user/message` 规范载荷的识别，保留本轮回应对象，不让记忆等 runtime-context 注入重置接话状态。

## 0.4.0：通用角色与历史继承

角色名在“角色 · QQ → 连接配置 → 角色会话配置”填写，QQ 联动情绪会使用这个称呼；改名不改变内部 personaId 或现有聊天 ID。引导、主动联系和错误文案去除固定姓名。新环境默认称呼为“角色”。

插件包名、nia_* 工具名、服务/路由/存储目录和默认数据标识保持兼容。它们是内部标识，不代表角色姓名。换角色继续继承原数据时，保持原 personaId，不复制或重绑会话，也不改写旧事件中的名字。更换角色卡时，手动同步情绪设置的人格摘要；本插件不会自动覆盖用户的角色卡和摘要。

此版本不提供同时多角色运行或切换时隔离数据。136 项回归通过；设置页在隔离环境实际验证保存、刷新与旧摘要保留。更新后需重启 DSH 后端。


使用 SnowLuma 的 OneBot v11 Universal WebSocket，保留自动发现好友/群、首聊自动绑定、稳定会话恢复、自主称呼和名称管理。
保留与妮娅记忆、情绪 0.2.2 的联动和持久化跨聊天联系队列，恢复原 QQ Bridge 的主要聊天能力。无需更换 SnowLuma。
状态：已完成本地测试和隔离浏览器交互验证；尚未完成正式 DSH 窗口及真实模型、QQ 往返验证。使用本地链接安装时，更新源码后需重新加载插件或重启 DSH。
旧版连接器曾通过本机 SnowLuma 只读检查；这不等于本版已通过真实端到端验证。

## 安装与启用

使用 DSH 插件管理器安装 QQ、记忆和情绪三个 0.4.0 本地包。没有发布到 npm，请指定本地来源，不要仅填包名。
也可用本地目录：`link:C:/Users/jellyStone/Documents/Codex/2026-10-26/kan/outputs/dsh-nia-qq`。
本地链接依赖该目录一直存在；迁移时建议使用固定版本 tgz 包。

1. 停止旧 QQ Bridge 对同一个账号的收发，避免重复处理。新插件不会自动关闭或卸载旧插件。
2. 安装记忆、情绪和 QQ 三个插件，按 DSH 提示重新加载。
3. 在“妮娅 · QQ”填写本机 WS 地址、令牌、登录 QQ 号；令牌留空保存会保留旧值。
4. 从已打开的妮娅会话“填入模板配置”，获取模型、预设和工作目录。不会复制模板聊天历史或局部提示词；必要时指定人设文件。
5. 填写你的 QQ 号；人格标识保持 nia；勾选“联动妮娅记忆与情绪”。首次保留预演，再启用接入。
6. 使用测试聊天验证模型、记忆、情绪和联系意图。预演不发 QQ 消息、不改名，但会调用模型。
7. 确认正常后关闭预演并保存，正式会话使用独立历史。预演内容不会补发。

默认未启用接入、联动关闭、预演开启。联动开关关闭时保留原独立 QQ 接入行为；打开后缺少记忆/情绪服务会阻止投递并报告失败，不悄悄退化。
只接受本机 WS 地址。Node 需提供 WebSocket（22+）；模型与 DSH 原生会话持久化服务须可用。

## 设置界面

角色名默认“妮娅”。启动接入时注册工作目录对应的 DSH 工作区，新建 QQ 会话会显式加入该工作区，并自动命名为“QQ 私聊 · 联系人”或“QQ 群聊 · 群名”；预演有单独前缀，已有非空标题保留。读取模板时保留已设置的工作目录。旧会话恢复时遵循其原工作目录，不自动移动或丢弃旧上下文。

面板分为“连接配置”“聊天”“消息与联系”“操作记录”。连接配置为草稿，修改后点击底部“保存设置并重连”；未启用接入时保存不会开启连接。“撤销修改”恢复已保存值。
“填入模板配置”只填写模型、预设和工作目录，保留其他未保存字段；不会立即保存或重连。模板下拉框显示已打开会话的标题，可搜索。聊天页区分正式与预演会话，联系意图处理完成不等于 QQ 已发送，以操作回执为准。

## 工具与自主联系

- nia_qq_say：向当前聊天发一条文本。可以分段，也可以不回复。默认普通 assistant 文本不自动发 QQ；可启用“自动转发最终回复”。
- nia_qq_media：发送本地/远程图片、已有音频文件或带引用的文字；图片、引用和文字也可一起发送。不能凭空合成语音。
- nia_qq_reply_gate：在有效 QQ 群聊轮次选择是否接话；不接话时阻止后续发送，正常结束，不强制 cancel。
- nia_qq_chats：只读列出当前机器人账号已接入的群聊和私聊，返回稳定 chatId，不发送消息。
- nia_qq_address：为当前聊天已认识的人选称呼，按账号身份跨群/私聊一致识别；联动时同步人物目录。
- nia_qq_rename：修改好友备注、自己在当前群的名片或自己 QQ 昵称；受平台权限约束。
- nia_qq_contact（联动）：提供目标 actorId、缘由、来源事件和 requestId，排队唤醒目标私聊，由目标会话结合原有语境决定说什么或取消。

联系只面向已有可用私聊的人物。不根据任意 QQ 号开辟陌生联系，不自动批准加好友/加群请求。
新好友通知、自己入群和首次来消息会自动建立映射；实际 Agent 在需要聊天时创建/恢复。
源事件能引发不同选择，不写“被骂必告状”的脚本。目标私聊收到的是妮娅自己的意图，不伪装成用户发言。
同一源事件对同一目标的联系去重；每人格每小时最多 6 次主动联系。一次联系唤醒不能递归转接，防止两个窗口反复互相唤醒。
原聊天或目标聊天暂停、插件停用时不再开始新的联系；已发出的网络请求不能撤回。

## 队列与恢复

最多同时处理两个聊天；同一个聊天等待上一轮空闲。消息默认从最后一条重新计时，停顿 3 秒合并；从首条起最长 12 秒、每批最多 20 条。两个时间可在“接话节奏”设置。生成期间新消息按下述 0.3.1 的相关性与让话规则处理；触发让话时未发送的旧回复返回 deferred，保留新消息等待下一轮；已经发送的不撤回。最长等待约束合并窗口，不保证模型或网络在 12 秒内完成回复。
请求立即排队，不在源会话等待目标会话结束。状态为 pending、delivering、accepted、handled、failed、uncertain、discarded。
handled 仅表示目标处理完意图，可能选择没发言；实际发送是否成功以操作回执为准。
在接收/发送交界处崩溃时标记 uncertain，不自动重放。failed 才能安全重试；面板可查看与忽略。
相同外发 requestId 不重复发送；结果未知时不要换 ID 重发。文本通过 OneBot text 段发送，不执行正文内 CQ 指令。
QQ 已确认但记忆同步失败时，保留确认结果；复用原 requestId 可补记回执，不再发一次。
本版提供有界历史补收、图片附件传递、可配置语音转写、分享卡片和合并转发解析；图片理解由所选模型决定，仍不提供独立空闲定时唤醒。

## 0.3.0 恢复的聊天能力

### 收消息与接话

0.3.0 默认 batchMode=sender，同一个聊天、同一个人连续发的消息分成一批；换人就分批，保留消息原顺序。可选 chat 模式，把整个聊天的待处理消息一起交给她，每条仍标记发言人。batchMs=0 关闭合并，一条一批。原版默认是同人合并、停顿 1 秒、最长 20 秒、每 2 秒拉历史；本版使用 WebSocket 实时接收，默认停顿 3 秒、最长 12 秒、每批 20 条，不覆盖你已经保存的时间参数。

同人模式分批不代表必须每批回复：0.3.1 按相关性和连续让话上限处理待收消息，无关背景不再阻塞当前回复。模型、情绪判断、队列占用和网络仍可能增加实际响应时间。

群消息接收范围可选 all（所有人，默认）或 directed（配置的用户、@ 机器人、引用本插件已确认发出的消息）。回复门槛默认开启，但由模型决定是否调用静默工具；不是关键词自动判定器，也不保证一定不插话。仅收到 @ 不强制回复。

### 发消息

splitReplies 默认开启，按空行拆段，不把每个句号或固定字数拆成一条。replyIntervalMs 默认 450，可设 0–5000。一次最多 30 段文字，总文本最多 16000 字。同一聊天发送串行，每一段独立记成功回执；相关新消息触发让话后未发送的余段永久取消，不在稍后偷偷补发。已发消息不会撤回。确认过的请求复用 ID 不重复发送，未知结果停止后续段落。

Markdown 图片会从正文抽出，按原版方式在文字段之后发送。也可以调用 nia_qq_media 指定 images、record、replyTo。文本始终使用 OneBot text 段，字面 CQ 字符不会被执行。

可选自动转发：只转 completed 回合最后一条 assistant 消息。若同轮已使用发送工具，则不重复转发。支持只发 [QQ] 块、仅发 QQ 唤醒回合，QQ 唤醒后续回合保留 90 秒；本机手动输入清除唤醒来源。默认保持工具发送，不自动转发。

### 图片、语音、卡片和引用

图片默认每批 4 张、单张 5 MB，可配置。支持 PNG/JPEG/GIF/WebP、普通图片和能获取地址的大表情；下载失败保留占位，不声称已看图。经 DSH attachments 服务交给模型，模型需要支持看图。原图及附件映射保存在 nia-qq/media，原 GIF 回发不使用宿主转换后的静态副本。相对发送路径优先图片根目录，否则当前 QQ 会话实际工作目录；支持 file URL。

引用消息通过 get_msg 取原文；分享 JSON/XML 卡片提取标题、描述、链接、BV 号。合并转发最多展开两层、30 个节点、16000 字；第一层图片与顶层共用张数上限，第二层仅保留图片标记。QQ 系统表情保留编号，不能取图的大表情保留摘要。

语音转写默认关闭。先请求 get_record 转 WAV，失败时下载原音频；可配置 FFmpeg 转换。转写程序与参数分开，参数采用 JSON 字符串数组，{file} 替换成本地音频路径，shell=false。附 tools/asr_cli.py（原作者 MIT 许可）作为 SenseVoice/sherpa-onnx 示例，环境需要原脚本注明的依赖和模型。本机原 QQ Bridge 未开启语音转写、未配置模型，升级不会自动安装大型模型。恢复的是转写和音频文件发送接口，不包含自动 TTS、浏览器朗读录音或桌面录音看门狗。

### 断线补收与迁移

初次启用为每个聊天记录当前起点，不把历史全部倒入。此后每次重连及每分钟检查最近历史，默认只补最近 10 分钟，每个聊天最多 100 条；按聊天和 message_id 去重，与实时消息共用队列。接口失败保留水位以便重试。超过 100 条会提示可能缺失；不承诺无限历史回补。暂停聊天期间不会从历史补收。

state.json 新增 history 和 outbox，原 sessionId、联系人与旧记录保留；没有迁移旧会话。迁移电脑要带走整个 nia-qq/media 和 state.json，同时迁移 DSH 原生会话、记忆和情绪目录。已保存的绝对文件路径可能需要在新机调整。

### 验证范围

本地联合测试与隔离设置页通过；另对本机 SnowLuma 的 get_friend_msg_history、get_group_msg_history、get_msg 做了只读验证。不发真实 QQ 测试消息，不调用真实模型。图片/语音真实端到端效果需在重载后以实际媒体测试。

## 0.3.1 接话与打断

默认 batchMode=adaptive：私聊保留同人合并，群聊把不同人的连续发言放入同批、保留各自身份；sender/chat 两个旧模式仍可选。已有时间参数不覆盖。

群聊默认 interruptPolicy=related：根据当前回应对象、明确 @、开头称呼和引用消息判断。正在回应的人继续补充、他人 @ 她或引用焦点消息属于相关；同一人明确 @ 其他人或引用其他话题时作为背景。群里其他人的消息继续排队，不标记已读，不因为没打断就丢弃。可选 all，让所有新消息都参与判断。

maxReplyYields 默认 2：同一连续接话过程，普通相关补充最多连续让话两轮；达到后可以先回应已读部分，未读仍在队列。相关的“先别发、等我说完、我说错了、改成”等暂停或纠正不受次数限制。私聊仍为新补充让话，不应用群聊上限。新的正常对话、成功发送或重新加载会重置连续次数。

发送工具可附 focusMessageIds 指定本轮已读消息（不允许空列表、未读或其他聊天消息）。默认焦点为本批直接提及她的消息，否则为本批最后发言人。并行调用保留各自焦点；旧轮次排队内容在进入新轮次后不继续发送。让话后不能靠更换 requestId 或焦点重新发送旧内容。回执去重、预演、静默及暂停规则仍有效。

相关性采用人物/引用规则和有限词语识别，不是语义分类模型；可能误判同一人换话题、隐含纠正或无 @ 的新话题。不额外调用分类模型，也不保证模型每次都选择最合适的焦点。明确纠正持续到来时仍可能继续等待，这是为了避免发出已知需要修正的内容。

此版未修改人格文件、记忆或情绪插件；未安装语音依赖、录音看门狗或旧插件更新器。100 项联合隔离测试通过，设置页保存/刷新验证通过；真实 QQ/模型接话效果需要重新加载后实测。


## 0.3.2：一键安装语音转写依赖

QQ 设置 → 语音转写 → 一键安装语音依赖。先保存或撤销未保存修改。安装任务在后台执行；设置页显示阶段和模型下载字节，支持取消、重试，关闭设置页不会中止任务，退出或重载插件会取消安装。安装期间阻止保存设置，避免旧表单覆盖新路径。

依赖本机已有的 64 位 Python 3.9–3.12（自动探测 py -3、python、python3）。创建独立 venv，固定安装 sherpa-onnx 2.0.0、numpy 2.0.2、imageio-ffmpeg 0.6.0；pip 仅允许二进制包，使用官方 PyPI，不更改全局 Python 环境。模型为 SenseVoice int8。模型约 230 MB，建议连同环境预留至少 1 GB；实际占用视平台与缓存而变。

默认路径为 DSH_HOME/nia-qq/asr；未指定 DSH_HOME 时为用户 .dsh/nia-qq/asr。Hugging Face 元数据提供提交号及校验摘要，按该提交下载 model.int8.onnx、tokens.txt；检查大小和 SHA-256 / Git blob 哈希，通过后才替换正式文件。重试复用通过校验的完整模型，不续传未完成的 .part 文件。需要能访问 PyPI 和 Hugging Face；没有自动绕过网络限制或添加第三方镜像。

完成后实际加载识别器、解码一秒静音并检查 FFmpeg 可执行，再自动保存三个路径字段。启用开关保持原值；首次安装需自行开启“启用语音转写”并保存。失败/取消不改配置；重启发现上次中断时显示重试，不自动下载。总超时 30 分钟，取消会终止安装进程树。

本次仅实现并测试安装功能，没有在用户正式环境下载完整模型或开启转写。通过本地联合测试、下载完整性测试、隔离 UI 的模拟进度/取消/重试/路径保存/开关保存验证。完整在线安装及真实 QQ 语音识别尚待实测。浏览器朗读录音和语音条输出未加入。

## 0.3.5：临时私聊的历史补收兼容

非好友临时私聊保留实时接收，但不调用 SnowLuma 的好友历史接口，也不推进虚假的补收位置。加为好友后可恢复历史补收。补收异常标明具体聊天；下一次补收成功后清除对应提示，其他错误不随之清除。聊天页标明非好友临时私聊的限制。此项不等于已完成系统账号识别或过滤。120 项回归通过；在实际 SnowLuma 上只读验证 5 个有效聊天历史接口成功，未调用失败临时账号、未外发或改写正式数据。后端需重启后生效。

## 0.3.6：失败重试的消息顺序与诊断路径

保留失败消息自动重试，按聊天等待 5/10/20/40 秒退避，本次运行连续失败达到 5 次后等待手动重试或忽略。旧失败消息阻止同一聊天的新消息越过它，其他聊天继续运行。恢复后沿用原有拆批、合并策略；只重置当前选中的失败批次，后续失败记录不会提前变成待处理并绕过退避。可能已接收的 uncertain 记录不自动重放。

错误日志写在实际 Store 数据目录中的 debug.log，因此跟随 DSH_HOME；隐藏配置的连接令牌并限制每条错误堆栈长度。保留 0.3.5 的非好友临时私聊实时接收逻辑。

结果未知的 QQ 操作核查后，可在“操作记录”点击“已核查，解除续接等待”。它只记录 continuationReviewedAt，不改 uncertain 状态、不宣称发送成功、不重试外发。
